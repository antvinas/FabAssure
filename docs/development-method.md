# 개발 방법

구현에 앞서 판단 기준, 역할 분리, 근거 요건을 먼저 정의했습니다. 무엇을 변경으로 볼지, 어떤 기준을 측정 전에 승인할지, 누가 무엇을 결정할 수 없는지, 어떤 기록만 근거로 인정할지, 수락 후 무엇으로 효과를 확인할지를 제품 계약으로 적고, 각 계약을 자동 테스트로 옮겼습니다.

진행 순서는 계약 → 구현 → 자동 테스트 → 오프라인 번들 검증 → 실제 브라우저 확인입니다. 계약에 없는 동작은 추가하지 않았고, 테스트가 실패하면 테스트가 아니라 구현을 고쳤습니다.

구현과 검토에는 AI 코딩 도구(Codex, Claude)를 사용했습니다. 도구가 만든 코드는 같은 테스트와 실행 확인을 통과해야 반영했으며, 제품 실행 경로에는 외부 AI 호출이 없습니다.
