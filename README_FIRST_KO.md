# FabAssure 시작 안내

FabAssure는 제조 변경을 변경 → 검증 → 근거 → 검토 → 수락 → 효과성 순서로 기록하는 Windows x64 오프라인 앱입니다. 샘플 데이터로 동작하며, 실행에 로그인·API 키·별도 Node 설치·인터넷 연결이 필요하지 않습니다.

## 시작과 종료

1. 이 폴더를 쓰기 가능한 로컬 위치에 둡니다. 폴더 안의 `runtime`, `src`, `assets`, 명령 파일을 함께 유지합니다.
2. `start-fabassure.cmd`를 실행하고 콘솔에 표시되는 로컬 주소를 확인합니다.
3. 같은 PC의 브라우저에서 `http://127.0.0.1:4310`을 엽니다. 포트가 이미 사용 중이면 앱은 다른 주소로 전환하지 않고 오류를 표시합니다.
4. 작업을 마치면 **실행 중인 콘솔에서 `Ctrl+C`**를 눌러 서버를 종료합니다. Windows가 `Terminate batch job (Y/N)?`를 묻는 경우 `Y`를 입력합니다. 브라우저 탭만 닫아서는 서버가 종료되지 않습니다. 별도 종료 명령 파일은 제공하지 않습니다.

첫 시작에서 샘플 SQLite 데이터가 `data/fabassure-demo.sqlite`에 생성됩니다. 이후 시작은 이 파일의 이력과 감사 기록을 이어 사용합니다.

## 로컬 검증

앱을 종료한 뒤 `verify-offline.cmd`를 실행합니다. 종료 코드 0과 JSON의 `status: pass`가 나오면 번들 파일 해시, 고정 Node 버전, 루프백 자산, 제한된 외부 연결 거부 시험, 샘플 Change 승인 시나리오가 통과한 것입니다. 다른 프로세스가 4310 포트를 사용하면 검증은 실패합니다. 이 검증은 PC의 네트워크를 끊거나 OS 방화벽 전체를 증명하지 않습니다.

## 합성 데이터 초기화

초기화는 **현재 기록을 새 샘플 데이터로 교체하는 결정**입니다. 먼저 앱을 `Ctrl+C`로 종료하고, 필요한 이전 기록이 있는지 확인한 뒤 `reset-demo.cmd`를 실행하세요. 정상 초기화는 기존 SQLite 파일을 `data/backups` (`data\backups`)에 로컬 백업한 다음 새 데이터 인스턴스를 만듭니다. 명령이 실패하면 오류를 확인하고 기존 DB나 `.pending` 파일을 임의로 삭제하지 마세요. 초기화를 원하지 않는다면 이 명령을 실행할 필요가 없습니다.

## 범위

앱은 `127.0.0.1:4310`에만 바인딩되고 번들된 로컬 파일을 사용합니다. 외부 서비스, 원격 API, CDN, 원격 DB, 텔레메트리를 실행 경로에 두지 않습니다.
